# 대상 AI별 프롬프트 최적화 지침

프롬프트를 어느 AI에 보내느냐에 따라 어떻게 다시 써야 하는지를 모은 파일이다.
**이 프로젝트에서 품질을 결정하는 핵심 자산**이고, 쓰면서 계속 고쳐 나가는 것을 전제로 한다.

두 곳에서 함께 읽는다:

- 확장: `src/shared/promptTargets.ts`가 `?raw`로 읽어 Gemini 재작성 요청에 끼워 넣는다
- Claude Code: `optimize-prompt` 스킬이 이 파일을 직접 읽는다

## 편집 규칙

- `## <이름>`이 섹션 키다. 이름은 `src/shared/sites.ts`의 `displayName`과 맞춘다.
- `## 공통`은 어느 대상에든 항상 함께 쓰인다.
- 각 항목은 **재작성하는 쪽에 주는 지시**로 쓴다. 일반론이 아니라 "이렇게 바꿔라"로.
- 확신도를 구분해 둔다. 표시가 없으면 벤더 문서나 널리 확립된 관행이고,
  `(추정)`은 경험적 짐작이라 쓰면서 검증·수정해야 한다.

## 공통

대상이 무엇이든 아래는 품질에 가장 크게 기여한다. 대상별 지침보다 먼저 적용한다.

- 목표를 첫 문장에 둔다. 무엇을 원하는지 모호하면 다른 어떤 기법도 소용없다.
- 인터뷰에서 나온 조건은 흩뿌리지 말고 한 곳에 모아 목록으로 만든다.
- 출력 형식을 지정한다. 길이, 구조, 언어, 코드 포함 여부.
- 판단이 필요한 지점에서 기준을 준다. "적절히"는 지시가 아니다.
- 원본에 없던 요구사항을 새로 만들어내지 않는다. 표현만 바꾸고 의미는 보존한다.
- 부정형("~하지 마")보다 긍정형("~하라")이 안정적이다. 금지가 꼭 필요하면 대안을 함께 준다.
- **요청 크기에 최적화 강도를 맞춘다.** 한두 문장으로 답할 질문에 역할 지정·형식 예시·헤더
  구조를 씌우지 않는다. 구조가 답변 품질을 바꾸지 않는 지점에서 멈춘다. 아래 대상별 지침은
  적용할 수 있는 기법의 목록이고, 전부 적용하라는 뜻이 아니다.

## Claude

구조를 태그로 명시하는 것에 가장 잘 반응한다.

- 섹션을 XML 유사 태그로 감싼다: `<context>`, `<task>`, `<constraints>`, `<example>`.
  태그 이름은 내용을 설명하는 것으로 자유롭게 정해도 된다.
- **긴 자료를 지시문보다 먼저** 둔다. 문서·코드·데이터가 위, 그것으로 무엇을 할지가 아래.
  순서가 뒤바뀌면 긴 입력에서 지시를 놓치기 쉽다.
- 복잡한 작업이면 결론 전에 사고 과정을 요청한다. 단순한 작업에는 넣지 않는다 — 장황해진다.
- 예시를 줄 때는 각 예시를 태그로 감싸 경계를 분명히 한다.
- 역할 부여가 통하지만 과장하지 않는다. "너는 20년 경력의 천재 개발자다"보다
  "이 코드베이스의 규약을 따르는 리뷰어"처럼 구체적 역할이 낫다.
- 출력만 원할 때는 "설명 없이 결과만"을 명시한다. 기본적으로 맥락을 덧붙이는 편이다.

## ChatGPT

역할 지정과 출력 형식 예시에 잘 반응한다.

- 마크다운 헤더(`##`)로 섹션을 나눈다. Claude의 태그 자리에 헤더가 들어가는 셈이다.
- 역할을 첫 줄에 지정한다: "너는 ~ 전문가다" 형태가 실제로 결과를 바꾼다.
- **출력 형식을 예시로 보여준다.** 말로 설명하는 것보다 원하는 모양을 한 번 보여주는 게
  훨씬 정확하다. 이 대상에서 효과가 가장 큰 기법이다.
- 제약은 번호를 매겨 나열한다. 산문에 섞으면 일부를 흘린다.
- 길게 답하는 경향이 있으니 간결함이 필요하면 명시적으로 요구한다.
  "3문단 이내", "불릿 5개 이하"처럼 숫자로.
- 단계가 많은 작업은 단계를 나눠 번호로 준다.

## Gemini

명시적인 절차와 형식 지정을 선호한다.

- 할 일을 번호 매긴 단계로 분해한다.
- 출력 형식을 구조로 지정한다(표, JSON, 불릿 등).
- 긍정형 지시가 특히 안정적이다. (추정)

## Perplexity

검색 기반 답변 도구다. 생성이 아니라 조사를 맡긴다는 전제로 다시 쓴다.

- **검색으로 답할 수 있는 질문 형태**로 바꾼다. 창작·긴 코드 생성 요청이면 애초에 대상이 틀렸다.
- 출처를 요구한다. 이 대상의 강점이다.
- 시점이 중요하면 명시한다("2026년 기준").
- 여러 질문을 한 프롬프트에 묶지 않는다. 하나씩이 정확하다. (추정)

## Grok

실시간 X(트위터) 데이터에 접근한다. 현재 진행 중인 화제나 여론이 필요할 때 유리하다.

- 시점과 범위를 좁혀준다("최근 일주일", "개발자 커뮤니티 반응").
- 어투가 캐주얼한 편이라 격식이 필요하면 명시한다. (추정)

## Copilot

Microsoft 생태계(Office, Windows, Azure)와 엮인 작업에 유리하다.

- 어느 도구·문서에 적용할 결과인지 밝힌다.
- 간결한 작업 지시를 선호한다. (추정)

## 이미지 생성

문장이 아니라 서술어 나열로 쓴다. 텍스트 AI와 규칙이 완전히 다르다.

- 쉼표로 구분된 서술어를 나열한다. 완전한 문장으로 쓰지 않는다.
- 순서: 피사체 → 스타일 → 조명 → 구도 → 화질.
- 부정 프롬프트를 지원하는 모델이면 원하지 않는 요소를 따로 모아준다.
- 추상적 형용사보다 구체적 명사가 강하다. "아름다운"보다 "황금빛 역광".
